# 按周期跳过除权除息的备选公式

记录日期：2026-11-21。

当前采用方案：两个单输出子指标 `GETXRS`、`GETXDS`。用户于本日反馈，实测速度恢复到与尚未采集除权除息的旧版接近的水平，并确认采用。创建步骤及完整推荐公式已同步到 [README](../README.MD#使用方式) 和 [调用说明](tdx_calling.md#完整公式)；原双输出方案继续保留备用。此次反馈为定性耗时对比，没有记录具体秒数，也不等同于事件数据逐项核对已经完成。

原方案由用户反馈能运行，比主公式直接调用 SPLITBARS 的版本快很多；与尚未采集除权除息的旧版相比，仍慢数倍。保留作为备用。以下周期判断按用户提供的写法，仅在日线采集事件。

对照基线是无事件采集的旧版，不是包含 SPLITBARS 的直接调用版本。剩余差距包含新增两次 SPLITBARS、两次 SPLIT 和指标引用等成本，不能仅凭总耗时归因于重复引用。

用户进一步反馈：单独运行日线导出明显慢，其他周期很快；SPLIT 本身成本不大；将 SPLIT 移入子指标的实测结果更慢。因此保留 SPLIT 在主公式，不再将搬动 SPLIT 作为提速方向，后续聚焦日线 SPLITBARS。

## 已能运行的备用方案

普通技术指标名称：`GETXRXD`。

```text
TESTSKIP(PERIOD!=5); {非日周期退出}
XRS:SPLITBARS(0,0),NODRAW;
{XR:SPLIT(0,0),NODRAW;}
XDS:SPLITBARS(0,1),NODRAW;
{XD:SPLIT(0,1),NODRAW;}
```

条件选股公式：

```text
START:=TDXDLL4(4,STR2CON(CODE),SETCODE,PERIOD); {重置数据并设置代码、市场和周期}
META:=TDXDLL4(5,START,TQFLAG,0); {检查不复权状态和支持的周期}
DT:=TDXDLL4(2,DATE,TIME,META); {复制原始日期时间，后台校验}
P1:=TDXDLL4(3,1,OPEN,CLOSE); {同时接收开盘价、收盘价}
P2:=TDXDLL4(3,2,HIGH,LOW); {同时接收最高价、最低价}
P3:=TDXDLL4(3,3,VOL,AMOUNT); {同时接收成交量、成交额，保留通达信原单位}
P4:=TDXDLL4(3,4,GETXRXD.XRS,SPLIT(0,0)); {除权：计数为0时，后台保存原值}
P5:=TDXDLL4(3,5,GETXRXD.XDS,SPLIT(0,1)); {除息：计数为0时，后台将原值乘10保存}
RESULT:=TDXDLL4(1,3,1,0); {将完整数据提交后台保存}
F:RESULT=1; {仅表示提交成功，CSV完成情况须看后台结果}
```

当前写法的两个检查点：

- 两次 `SPLIT` 位于主公式，非日线也会计算；子指标中的 `TESTSKIP` 无法跳过主公式的这两次求值。
- 主公式分别引用 `XRS`、`XDS`。是否共享同一次子指标计算，官方公开说明没有给出保证，重复求值目前只是待验证的性能假设。

`PERIOD!=5` 也会跳过周、月、年，不仅是分钟周期。被跳过的输出不能视为有效的事件周期数；本方案的反馈不代表周、月、年事件输出已经核对通过。

非日线只导出行情时，同时省略 P4、P5。需要周、月、年事件输入时，使用 [直接调用备用公式](tdx_calling.md#原主公式直接调用方案)。

## 已采用方案：两个单输出子指标（用户实测提速）

保留原 GETXRXD。另建普通技术指标 `GETXRS`：

```text
TESTSKIP(PERIOD!=5); {非日周期退出}
XRS:SPLITBARS(0,0),NODRAW;
```

另建普通技术指标 `GETXDS`：

```text
TESTSKIP(PERIOD!=5); {非日周期退出}
XDS:SPLITBARS(0,1),NODRAW;
```

以下两个独立条件选股公式可用于复现纯计算对照，不调用 DLL，不写 CSV。

A：原双输出子指标。

```text
RA:=GETXRXD.XRS;
DA:=GETXRXD.XDS;
XG:RA>=0 AND DA>=0;
```

B：两个单输出子指标。

```text
RB:=GETXRS.XRS;
DB:=GETXDS.XDS;
XG:RB>=0 AND DB>=0;
```

两版都以日线、相同股票和全部历史运行，比较结果和耗时；交替运行多轮，记录耗时。该对照用于区分引用组织方式的成本，不改变 SPLITBARS 的参数或事件判断。用户已反馈拆分写法明显提速，但尚无实际求值次数的跟踪证据，不能将内部重复计算当成已确认原因。

当前推荐的导出公式将 P4、P5 改成：

```text
P4:=TDXDLL4(3,4,GETXRS.XRS,SPLIT(0,0)); {除权：计数为0时，后台保存原值}
P5:=TDXDLL4(3,5,GETXDS.XDS,SPLIT(0,1)); {除息：计数为0时，后台将原值乘10保存}
```

其余导出步骤保持备用方案的原顺序。SPLIT 继续留在主公式，DLL 接口不变；日线仍完整查询两类事件的全部历史，相同比例重复事件仍由 SPLITBARS 定位。

## 已撤回的提速建议：一个子指标、一个合并输出

本方案没有减少 SPLITBARS 的计算次数，已撤回作为后续提速方向的建议，以下保留原理和对照公式供查阅。当前采用两个单输出子指标。合并输出是将两类事件是否发生合成一个数字，主公式只引用一次子指标；仍完整计算两次 SPLITBARS，不按比例变化推断事件，同值重复事件、同日两类事件均保留。

按“每次子指标引用都会完整执行其内部公式”的模型比较：原双输出指标引用两次，除权、除息各计算两次；当前两个单输出指标各引用一次，两类事件各计算一次；本方案只引用一次合并输出，两类事件也各计算一次。因此本方案没有继续减少 SPLITBARS 的计算次数，仅尝试减少一次子指标调用，并新增比较和算术，当前没有优于两个单输出方案的实测依据。这里的次数是该模型下的推导，不是终端内部调用跟踪结果。

本方案的必要条件是只写一次 `MF:=GETXFLAG.EVT`，后续复用这份结果，或一次交给 DLL 后由后台拆分。如果为了两类事件分别引用 `GETXFLAG.EVT`，就会回到双输出方案可能重复计算的问题。当前两个单输出指标已实测明显提速，本方案不作为下一步修改 DLL 的依据。

新建普通技术指标 `GETXFLAG`：

```text
TESTSKIP(PERIOD!=5); {非日周期退出}
EVT:(SPLITBARS(0,0)=0)+2*(SPLITBARS(0,1)=0),NODRAW; {合并两类事件标记}
```

输出含义：

| EVT | 当日除权 | 当日除息 |
| --- | --- | --- |
| 0 | 否 | 否 |
| 1 | 是 | 否 |
| 2 | 否 | 是 |
| 3 | 是 | 是 |

这是减少子指标引用的尝试，不是减少 SPLITBARS 查询的方案。它新增比较、乘法和加法；用户此前已观察到前台运算可能拖慢，因此只有实测更快才值得继续。官方没有保证该组织方式更快，也没有保证实际求值次数。

先以日线、同一组股票、全部历史，对照两个纯计算选股公式；交替运行至少三轮，记录耗时。它们筛选历史上发生过任意一类事件的品种，不调用 DLL、不写 CSV。

A：已提速的两个单输出子指标。

```text
RB:=GETXRS.XRS;
DB:=GETXDS.XDS;
XG:COUNT(RB=0 OR DB=0,0)>0;
```

B：一个合并输出。

```text
MF:=GETXFLAG.EVT;
XG:COUNT(MF>0,0)>0;
```

耗时对照以外，可另运行以下核对公式，查找任一历史周期的标记差异；它同时计算两套方案，仅核对数据，不能用于比较速度。

```text
MF:=GETXFLAG.EVT;
RB:=GETXRS.XRS;
DB:=GETXDS.XDS;
MR:=MOD(MF,2);
MD:=INTPART(MF/2);
XG:COUNT((MR!=(RB=0)) OR (MD!=(DB=0)),0)>0;
```

核对公式选出的品种需要逐日检查；未选出差异的结果也应结合已知同值重复事件、同日两类事件的样本确认。

当前 DLL 类型 4、5 接收的是各自的周期数，并以等于 0 判断事件。EVT 的 0 代表无事件，含义不同，不能直接传给现有接口，否则会误判。本节仅供纯公式测试；若明显提速，再单独设计 DLL 接收标记及后台拆分，SPLIT 仍留在主公式。当前程序没有实现这一接收方式。

## 补充检索结论（2026-11-21）

本轮核对官方函数列表、指标引用及脚本控制说明，没有找到同时满足单一通达信、全部历史、同值重复事件完整识别，并有依据可明显降低当前两次 SPLITBARS 成本的替代方案。该结论是本次检索结果，不是对所有未公开实现的断言。用户随后确认采用已获提速反馈的 GETXRS、GETXDS 两个单输出子指标。

| 检查方向 | 官方定义或可确认事实 | 本工程的判断 |
| --- | --- | --- |
| FINANCE(49) | 今日权息标识：0 无、1 分红、2 送转股、3 分红和送转股、4 配股 | 定义是今日标识，不能据此代替逐日历史事件序列；改变当前要求后才可能有用途 |
| SPLITBARS(0,2) | 返回送转股或分红到当前的周期数 | 合并了事件类别，无法可靠区分只除权、只除息或两者同日发生；配合 SPLIT 值变化仍有同值重复事件的歧义 |
| DIVFACTOR | 返回按指定复权方式得到的数值 | 接口没有给出两类事件各自的发生标记，没有找到能完整还原两类事件且更快的可靠方法 |
| CALCSTOCKINDEX | 返回指定品种、指标及输出的计算值 | 换一个引用入口，不直接减少事件函数计算；官方没有给出可据此保证提速的缓存契约 |
| SIGNALS_SYS、EXTDATA_USER | 读取官方提供或自行设置、刷新的序列数据 | 没有核实到可直接提供全历史两类事件的官方字段及覆盖保证；不能凭函数名称替换现有输入 |

SPLIT 值变化、IFC、把 SPLIT 移入子指标、合并标记，以及另建外部数据采集流程，均不作为本轮新增推荐。原有性能反馈保留，不将未在终端运行的新公式记为实测通过。

## 验证条件

两个单输出方案已获得用户的终端提速反馈并确认采用。以下保留结果完整性与可重复耗时的核对条件；没有提供的核对结果不记为通过。

1. 纯计算 A/B 的股票、周期和使用数据范围相同，比较选股结果及耗时，避免把后台队列等待或 CSV 读写算进函数差异。
2. 接入导出前，先在独立 CSV 目录对照少量日线品种，核对价格、事件列、已知事件日及同值重复事件。
3. 比较完整导出时保持后台线程等配置一致，每轮开始前排空，完成后也分别排空确认结果。
4. 分钟线应正常提交行情且事件列为空；周、月、年继续受当前 PERIOD!=5 判断影响，需另行核对。

当前记录：双输出方案可运行但日线较慢；两个单输出方案已实测提速；将 SPLIT 移入子指标已实测更慢，不再作为提速建议。对这些方案的判断以终端实测为准。
