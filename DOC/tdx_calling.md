# 通达信 DLL 调用顺序

本版按单线程、每个品种完整执行后再处理下一品种使用，不再生成批次编号。DLL 和公式应配套更新。

## 准备

1. 配套复制 DLL 和 32 位 SaveAsCSVWorker.exe，默认放在同一目录，再绑定 DLL 并新建条件选股公式；绑定注册接口时自动启动后台，启动失败则绑定失败并记录日志。可用 INI 的 async.worker_path 指定相对于 DLL 的后台路径。下方按第 4 号绑定编写；其他编号统一替换 TDXDLL4 中的 4。
2. 使用数据选“全部”，提前下载所需历史数据。
3. 使用不复权数据；本版核对 TQFLAG=0，与当前 CVStoDB 入库约定一致。
4. 一次计算只导出一个品种、一个周期；整条调用链必须在同一线程依次执行，完成或失败后从开始步骤处理下一品种，不交错调用。

每次开始先清空本线程上一次处理状态。各步骤只返回接收或提交成功 1、失败 -1，并通过上一项的结果建立调用依赖；行情内容的逐条校验在后台执行。

## 完整公式

    START:=TDXDLL4(4,STR2CON(CODE),SETCODE,PERIOD); {重置数据并设置代码、市场和周期}
    META:=TDXDLL4(5,START,TQFLAG,0); {检查不复权状态和支持的周期}
    DT:=TDXDLL4(2,DATE,TIME,META); {复制原始日期时间，后台校验}
    P1:=TDXDLL4(3,1,OPEN,DT); {复制开盘价，后台校验}
    P2:=TDXDLL4(3,2,CLOSE,P1); {复制收盘价，后台校验}
    P3:=TDXDLL4(3,3,HIGH,P2); {复制最高价，后台校验}
    P4:=TDXDLL4(3,4,LOW,P3); {复制最低价，后台校验}
    P5:=TDXDLL4(3,5,VOL,P4); {复制成交量，按通达信原值保存}
    P6:=TDXDLL4(3,6,AMOUNT,P5); {复制成交额，按通达信原值保存}
    RESULT:=TDXDLL4(1,3,P6,0); {将完整数据提交后台保存}
    F:RESULT=1; {仅表示提交成功，CSV完成情况须看后台结果}

采集与提交步骤成功返回 1，失败返回 -1。日期和数值接口的 1 只表示数组已独立复制；日期、HHMM、升序、有限数值、量额和价格关系的错误改由后台报告。前台仍拒绝空指针、条数或调用顺序不一致、上一步失败及不合法元数据。最终选股结果表示任务已提交，后台此时可能尚未更新 CSV。中途失败应重新运行完整公式，不要只重试保存。行情校验、已有 CSV 读取、校验及替换失败均保留旧文件，并使本轮最终排空返回失败。

公式通过上一项结果建立调用依赖，不再以恒定 F:1 代表成功。所有数组的 nCount 必须与开始调用一致，六组数值按上述顺序各传一次。重复保存失败。

每次导出仍按“代码.市场.周期.csv”合并同一个文件：已有日期更新、新日期补入、旧历史保留，不按执行次数保存副本。合并结果未变化时跳过 CSV 写盘；有变化时完整写入临时文件再替换原文件，成功后不保留临时副本。

## 扫描结束后的排空停机

停止选股扫描后，单独对一只股票运行以下条件选股公式一次，等待调用返回；不要把它加入每只股票的导出公式末尾，也不要选择全市场重复执行。

    ENDRESULT:=TDXDLL4(7,0,0,0); {停止接收，等待已提交任务处理完并停止后台}
    F:ENDRESULT=1; {本轮无接收、提交及保存错误才为真}

返回 -1 时查看日志中的失败品种和原因。当前线程若还有未提交的部分采集，也会记为中止失败并释放，须重新导出该品种。已成功的文件保持成功；修正问题后重新导出失败品种。完成此次排空后，下一次开始会建立新一轮统计并按需启动后台。

运行 CVStoDB 入库和更新程序前先完成排空，确认本轮结果。通达信退出或崩溃、DLL 真正卸载及重新注册接口时，旧后台立即终止，不等待已接收任务；要确认全部完成，必须先执行 7 号排空再退出或解绑。重新绑定会启动新后台并建立新通信标识，旧任务及旧错误统计不延续到新后台；后台自身被结束或关机也会丢失未保存任务。

## 查询与停止接收

需要查看状态时，可新建独立技术指标公式（有两项输出）：

    WAITNUM:TDXDLL4(6,0,0,0); {已接收但未完成的任务数，包含正在保存}
    HASERR:TDXDLL4(6,3,0,0); {有接收、提交或保存失败时为1，查询不清除记录}

6 号其他查询项目见 [接口约定](tdx_mapping.md)。采集预留与已接收任务分开查询；WAITNUM=0 还需检查 HASERR，并用 7 号完成停机。

CSV 目录中的 _bg_ 状态文件可直接查看后台负载，例如 _bg_12-1000_8-8 表示等待 12 个、正在保存 8 个。有任务时每 5 秒更新，全部完成变为 _bg_0-1000_0-8 并暂停刷新，新任务到来时恢复；它不代替 HASERR 或排空结果。完整规则见 [后台状态文件](使用说明.md#后台状态文件)。

后台默认最多 8 个不同文件同时保存；saveAsCVS.ini 的 [async] 段可设置 worker_threads=1—128，修改后先排空再开始。同一个 CSV 始终按提交顺序处理。需要观察实际并行数量时使用 TDXDLL4(6,2,0,0)，返回正在保存数 0—worker_threads。设置为 128 时，空闲状态文件为 _bg_0-1000_0-128。导出主公式及排空公式无需因并行数改变。

8 号调用 TDXDLL4(8,0,0,0) 可停止新增输入并唤醒资源等待者，已提交任务继续保存，之后仍须运行 7 号排空。停止接收会记录本轮中止，因此最终排空返回 -1；它不会把尚未完成的工作伪报为全部成功。

如果当前 DLL 调用已经阻塞，通达信界面不一定还能发起其他调用。可从 DLL 的 file 日志“连接独立后台”或后台日志“后台启动”中找到本轮 stop_event 完整值，在同一 Windows 用户和会话的 PowerShell 中执行：

```powershell
$stopEvent = [System.Threading.EventWaitHandle]::OpenExisting('在此填写日志中的完整 stop_event 值')
try { [void]$stopEvent.Set() } finally { $stopEvent.Dispose() }
```

这只通知本轮停止接收，200 毫秒间隔的检查会使等待调用尽快返回失败，实际时间还受调度和当前操作影响；不会强行终止保存线程或丢弃已提交任务。新一轮使用新的事件名，旧事件不影响重启。随后先排空，再处理失败并重导。不要假设界面的“停止选股”按钮一定能中断 DLL 内部等待。

## 周期

| 数据周期 | 通达信 PERIOD | CSV 周期 |
| --- | --- | --- |
| 1 分钟 | 0 | 1m |
| 5 分钟 | 1 | 5m |
| 15 分钟 | 2 | 15m |
| 30 分钟 | 3 | 30m |
| 60 分钟 | 4 | 60m |
| 日线 | 5 | 1d |
| 周线 | 6 | 1w |
| 月线 | 7 | 1mo |
| 年线 | 11 | 1y |

仅支持这九类周期。120 分钟和扩展周期已取消；季线、多分钟、多日、多秒及其他自定义周期也拒绝保存。5 号调用的第三个参数保留，必须传 0。

## 时间

- 传原始 DATE，由 DLL 加回 19000000，不要在公式中先加偏移。
- 分钟周期使用 TIME 的 HHMM 值，秒为 00；时间缺失或非法时拒绝保存。
- 日、周、月、年忽略 TIME，统一使用 default_time，默认 15:00:00；日期仍为终端该条数据的日期。
- ts 是通达信本地时间，例如 2026-10-16 15:00:00，不附时区、不做时区换算。
- 周标识由 DLL 从日期计算 ISO 周所属年份及周号，不再依赖 WEEKOFYEAR。例如 2019-12-31 属于 2020W01。

## 完整性边界

DLL 校验接收到的数据，不能证明终端已经下载全部历史。“使用数据为全部”不替代下载及覆盖范围核对。

当前尚未结束的一条数据也会导出，后续应重新运行完整公式更新。盘中日数据、尚未结束的周/月/年数据不能当作已完成的数据使用。同一周期标识下，较早日期不得覆盖较晚日期；同一时间戳的修正以本次终端数据为准，因为接口没有提供源数据版本。

失败时检查 DLL 目录日志，排除问题后重跑；不要在导出期间手工修改 CSV。

需要查看日志时，在 saveAsCVS.ini 中设置 mode=file、level=1，并重新启动通达信。配置及日志位置见 [使用说明](使用说明.md)。

需要手工删除数据行时，先停止导出并备份，使用纯文本编辑器删除完整行，保持表头、分隔符、编码和其余内容不变。Excel 打开后再保存可能改变文本格式，导致文件不符合 DLL 的读取约定；即使关闭 Excel 后重跑，也可能报“旧 CSV 无法完整读取或内容不合法，已停止覆盖”。此时先恢复备份或核对格式，再重跑；原文件只要仍有合法数据行，且终端重新传入被删日期，就会按原规则补回。

参数语义依据：[通达信官方函数列表](https://help.tdx.com.cn/gspt/docs/markdown/redword/functionlist.html)。
