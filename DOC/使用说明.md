# SaveAsCSV 配置与使用说明

## 安装与使用

1. 在 Windows 10/11 上，将配套的 `SaveAsCSV.dll` 和 `SaveAsCSVWorker.exe` 放到插件目录，绑定 DLL；注册接口时会自动启动并连接后台。Release / x86 发布版已包含 C++ 运行库，无需另装 Visual C++ 运行库或 .NET。
2. 按 [调用公式](tdx_calling.md) 新建条件选股公式，使用数据选择“全部”，提前下载历史数据并使用不复权数据。
3. 首次加载会在 DLL 同目录生成 `saveAsCVS.ini`；默认输出到该目录下的 `csv` 文件夹。
4. 停止扫描后，单独执行 7 号排空公式，确认本轮保存完成后再入库、更新程序、解绑 DLL 或退出通达信。公式提交成功不代表 CSV 已保存成功。

DLL 卸载或重新绑定时，旧后台立即结束，不等待队列；重新绑定会启动新后台。通达信退出时后台也会立即结束。未完成的内存任务会丢失，已经成功保存的 CSV 保留；旧后台的任务及统计不会带入新后台。

卸载或重绑前先停止选股，确保 DLL 接口调用已经返回；后台任务不必等完。需要保留全部任务时先运行排空公式。

## 配置文件

```ini
[log]
mode=file
level=1
file=saveAsCSV.log

[export]
csv_dir=
symbol_width=6
default_time=150000

[async]
queue_capacity=1000
queue_memory_mb=2048
worker_threads=8
worker_path=SaveAsCSVWorker.exe
```

| 配置项 | 说明 |
| --- | --- |
| log.mode | `file`、`debugview`、`console` 或 `disable` |
| log.level | 0 全部，1 信息及以上，2 警告及错误，3 仅错误 |
| log.file | 日志文件名；DLL 与后台分别记录日志，后台文件名带进程号 |
| csv_dir | 为空时使用 DLL 同目录的 `csv`；相对路径以 DLL 目录为基准 |
| symbol_width | 代码补零宽度，1—12 |
| default_time | 日、周、月、年的统一时间，格式为 HHMMSS，默认 150000 |
| queue_capacity | 采集预留及未完成任务总数上限，默认 1000，包含正在保存的任务 |
| queue_memory_mb | 后台任务数据额度，单位 MiB，默认 2048；不包含解析、合并等临时内存 |
| worker_threads | 同时保存的线程数，1—128，默认 8 |
| worker_path | 后台程序相对于 DLL 的路径，可写 `backend\SaveAsCSVWorker.exe` 或 `..\bin\SaveAsCSVWorker.exe`；不接受绝对路径 |

`export` 配置在每次开始导出时读取，随任务固定；修改 `async` 配置后先排空停机，再开始导出。日志配置在 DLL 加载或后台启动时读取。后台程序放到其他目录后，INI、日志和 CSV 相对路径的基准仍是 DLL 目录。

旧配置中的 `tz`、`append`、`symbol_suffix` 不再使用。时间按通达信本地时间保存，不添加时区、不做时区换算。

## 后台状态文件

后台在 CSV 目录创建或更新一个空文件：

    _bg_等待任务数-队列上限_正在保存数-线程上限

例如 `_bg_12-1000_8-8` 表示等待 12 个任务、正在保存 8 个。有任务时每 5 秒更新；全部完成后更新为 `_bg_0-1000_0-8` 并暂停刷新，新任务到来后恢复。等待数不包含正在保存及尚未提交的采集预留。

状态文件只表示负载，不代表保存全部成功；最终结果以日志和 7 号排空结果为准。通达信直接退出后可能保留最后一次状态，下次启动时重新更新。

## CSV 与结果检查

文件名为 `代码.市场.周期.csv`，例如 `600000.SH.1d.csv`。重复导出合并同一个文件，保留历史、更新已有日期并补入新日期；价格等数值保持六位有效数字输出。

新数据或旧 CSV 校验失败时保留原文件，错误写入日志。合并结果与原文件完全一致时跳过 CSV 写盘，日志记录“数据未变化，跳过写盘”；有变化时通过临时文件和替换操作保护旧文件。字段、时间及合并规则见 [输入输出约定](tdx_mapping.md)。

DLL 和后台日志位于 DLL 目录。日志记录提交、保存结果及错误原因；需要查看完整信息时设置 `mode=file`、`level=1`。队列清空仍需检查失败标志或执行排空，不能仅凭状态文件判断成功。

## 后台无法启动时

先确认 DLL 与后台 EXE 为当前 Release / x86 配套版本、`worker_path` 指向实际文件。发布版使用 `/MT`，即把所需 C++ 运行库编入各自文件，避免加载通达信或系统中的旧 `MSVCP140.dll`。后台需要由 DLL 带参数启动，直接双击后无窗口并退出是正常表现。

仅把语言标准从 C++17 改为 C++14 不能解决旧运行库问题；当前保留 C++17，并通过静态链接隔离运行库。旧动态链接版在较老运行库中首次加锁可能发生访问违规，见 [微软说明](https://github.com/microsoft/STL/issues/4730)。

设置 `mode=file`、`level=1`，重新启动通达信，按日志最后出现的位置排查：

| 最后出现的日志 | 检查方向 |
| --- | --- |
| DLL接口注册成功，未出现“首次进入导出接口” | 此时后台已启动并完成连接，核对公式、绑定编号及通达信的数据准备 |
| 首次进入导出接口，未出现“配置读取完成” | 检查输入及配置读取阶段 |
| 准备启动独立后台 | 检查程序创建是否返回，是否被系统安全软件拦截 |
| 创建独立后台失败 | 根据 `Windows=` 错误码检查路径、权限和程序文件 |
| 独立后台进程已创建，随后退出 | 根据 `exit_code=` 及后台日志检查运行库或后台初始化错误 |
| 连接独立后台 pid= | 后台已启动，应继续检查后续资源等待或保存错误 |

后台在握手前退出也会立即报告退出码；仍在运行但未能建立管道时，连接等待约 10 秒后报错。日志为空不能证明后台内存或队列已满，应先确认当前 DLL 是否真正收到公式调用。

如果通达信自身闪退，使用 Windows 可靠性监视器（运行 `perfmon /rel`）查看本次故障的模块名称、异常代码及偏移；这与正常返回失败的后台启动错误分开排查。

## 编译

使用 Visual Studio 2022 的 C++ v143 工具链及 Windows SDK 打开 `Stock_Indicator.sln`，选择 `Release / x86`，生成 DLL 与独立后台程序。两者应配套部署。
